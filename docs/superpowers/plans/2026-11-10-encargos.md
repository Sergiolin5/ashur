# Encargos al modelo local (0.46.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude (via the 0.45.0 connector) can order summarize / answer / classify jobs over Sergio's indexed documents; the core runs them on local models one window at a time, with Sergio approving the launch and, when the result returns to Claude, its release.

**Architecture:** New `core/encargos.py` holds everything that is pure: resolving documents from the index, the three operations as small classes that turn documents into work units and units into a result, and the line filters. `core/app.py` adds the runner (one worker thread, one unit at a time through `local_complete`), the approval hooks into the existing `claude_requests`, the panel endpoints and two connector tools. State lives in one new table `encargos`; the units (with their text snapshot) are stored as JSON so a restart resumes.

**Tech Stack:** Python 3, FastAPI, SQLite (FTS5 index already present), pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-10-encargos-design.md`

## Global Constraints

- Version **0.46.0**, core and panel only. No node code, updater or compose change; `CODE_PATHS` untouched. No new dependencies.
- One schema change only: table `encargos`.
- Documents come only from the index (`docs`, `doc_chunks`); nothing is read from disk. Index reads use their own connection (like `db.docs_search`).
- Caps: 20 documents per encargo; 30 windows per document; windows of 5000 characters; 3 unfinished encargos (`pending_approval`, `queued`, `running`, `paused`); result to Claude cut at 12 000 characters + «(el resto está en el panel)»; pregunta ≤500; motivo 3–300; categorías ≤10 of ≤40 characters; responder uses the best 6 fragments; clasificar reads ≤3000 characters per document; resumir condenses a document with more than 12 bullets to ≤8.
- One unit at a time across all encargos; 3 tries per unit, 30 s apart (reuse `NOTES_TRIES`, `NOTES_RETRY_WAIT_S`); waits while `queue_paused`.
- Nothing derived from document content reaches Claude unless the encargo is `released`. `kept` and every other state return no result text to Claude.
- Lines that look like secrets (`looks_like_secret`, `DIARY_SECRET`) are dropped from results.
- Logs carry counts only (documents, units, seconds, device) — never content, question, categories or motivo.
- Launch request push ignores quiet hours (like 0.45.0 requests); «Encargo listo» goes through `notify_due` (respects quiet hours), new category `encargos`.
- Spanish user-facing text; `CHANGELOG.md` row in English, commit message same text.

## Review Focus

1. A document whose text contains `"` or FTS operators (`AND`, `NEAR`, `*`) in the question: `responder` must not crash the FTS query — reuse `docs_search`'s quoting. Test in Task 2.
2. Core restarts while a unit's `llm` task is in flight: on resume the unit is redone, never counted twice. Test in Task 3.
3. Sergio rejects the launch request or cancels while `pending_approval`: the encargo leaves the unfinished count so a new one can be ordered. Test in Task 3.
4. A folder given with a trailing slash or Windows backslashes (`C:\Users\s\Docs\`): matches the same documents as without. Test in Task 2.
5. Claude polls `ashur_ver_encargo` for another encargo id, or a `kept` one: no result text. Test in Task 4.

**Interfaces — Produces (on `DB`):**
```sql
CREATE TABLE IF NOT EXISTS encargos (
    id INTEGER PRIMARY KEY AUTOINCREMENT, ts REAL NOT NULL, op TEXT NOT NULL,
    params TEXT NOT NULL DEFAULT '{}', to_claude INTEGER NOT NULL DEFAULT 0, reason TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL DEFAULT 'pending_approval', docs TEXT NOT NULL DEFAULT '[]',
    units TEXT NOT NULL DEFAULT '[]', done INTEGER NOT NULL DEFAULT 0, total INTEGER NOT NULL DEFAULT 0,

```

- `encargo_next() -> Optional[dict]` — the `running` or `paused` one first (resume), else oldest `queued`.
- `doc_texts(node_id, path) -> list[str]` — the document's chunks ordered by `seq`, own read-only connection.

### Task 2: `core/encargos.py` — documents and operations (pure)

**Files:** Create `core/encargos.py`. Test: `tests/test_encargos.py`.

**Interfaces — Produces:**
- Constants: `MAX_DOCS = 20`, `WINDOW = 5000`, `MAX_WINDOWS = 30`, `MAX_UNFINISHED = 3`, `CLAUDE_CUT = 12000`, `ANSWER_FRAGMENTS = 6`, `CLASSIFY_CHARS = 3000`, `CONDENSE_OVER = 12`, `CONDENSE_TO = 8`.
- `class EncargoError(Exception)` — Spanish, user-facing.
- `resolve_docs(db, busqueda: Optional[str], equipo: Optional[str], carpeta: Optional[str]) -> list[dict]` → `[{"node_id","path","name","chunks"}]`. Exactly one of busqueda / (equipo+carpeta) else `EncargoError`. Search: words via `Brain.file_words`-style tokenizing of the query → `db.docs_search(words, limit=MAX_DOCS, with_text=False, any_word=True)`. Folder: normalize `\`→`/`, strip trailing `/`, case-insensitive prefix match on `docs.path` for that node (own connection); more than `MAX_DOCS` → `EncargoError("La carpeta tiene N documentos leídos; el tope es 20. Pide una carpeta más concreta.")`. None found → `EncargoError("No encontré documentos leídos que coincidan.")`.
- `windows(chunks: list[str]) -> list[str]` — consecutive chunks joined until adding the next would pass `WINDOW` (a single chunk longer than `WINDOW` is split).
- `class Operation` with: `name: str`; `label(n_docs) -> str` (e.g. «resumir 7 documentos»); `first_units(docs: list[dict], texts: dict[str, list[str]], params: dict, fragments: Optional[list[dict]] = None) -> list[dict]` (texts keyed by `node_id + "\n" + path`); `after(unit: dict, answer: str, state: dict) -> list[dict]` (records into `state`, may return follow-up units); `render(state: dict, docs: list[dict], devices: dict) -> str`. A unit is `{"kind": str, "doc": int (index in docs) | None, "system": str, "text": str}`.
- `OPERATIONS: dict[str, Operation] = {"resumir": Resumir(), "responder": Responder(), "clasificar": Clasificar()}`.
- `clean_lines(text: str) -> list[str]` — non-empty stripped lines without secret-looking ones.
- Behavior (exact copy in prompts is the implementer's, Spanish, «solo lo que dice el texto, sin inventar»):
  - **Resumir:** one `window` unit per window (≤`MAX_WINDOWS` per doc; record `skipped[doc]=(MAX_WINDOWS, total)` when cut). `after` collects bullet lines (`-`,`•`,`*`) per doc; after a doc's last window, if it has > `CONDENSE_OVER` bullets, returns one `condense` unit with them. `render`: `## <name>` + bullets per doc (+ «(leí solo el principio: X de Y partes)» when cut) + footer «(N documentos, M trozos, hechos en dev (k), …)».
  - **Responder:** `first_units` receives `fragments` from the runner, which computes them with `best_fragments(db, docs, pregunta) -> list[dict]` (also in this module): `db.docs_search(words, limit=50, any_word=True, full=True)` filtered to the encargo's documents, first `ANSWER_FRAGMENTS`. No fragments → zero units and `render` returns «No está en estos documentos.». Else one `answer` unit whose text lists fragments as `[name] …`. `render`: the answer + footer.
  - **Clasificar:** one `classify` unit per doc with its first `CLASSIFY_CHARS`; with categories, answer is matched case-insensitively to one of them else «otra»; without, the first line cut to 4 words. `render`: `- <name> → <categoría>` lines + footer.

### Task 3: Runner, approval hooks, panel endpoints

**Files:** Modify `core/app.py`, `core/mcp.py` (`ACTIONS`, `action_label` formats with all args), `core/events.py`. Test: `tests/test_encargos.py`.

**Interfaces:**
- Consumes: Task 1 DB methods; Task 2 `OPERATIONS`, `windows`, `resolve_docs`, constants; existing `local_complete`, `queue_paused()`, `run_request`, `claude_request_reject`, `NOTIFY_CATS`, `notify_due`, maintenance loop (`app.state.*_due` around line 213).
- Produces:
  - `ACTIONS["encargo"] = "lanzar el encargo #{encargo}"`, `ACTIONS["cancelar_encargo"] = "cancelar el encargo #{encargo}"`; `action_label(action, args)` fills any placeholder from args (missing → «?»).
  - `run_request`: `encargo` → `db.encargo_set(id, expect="pending_approval", status="queued")` else not_done «El encargo ya no espera aprobación.»; `cancelar_encargo` → `cancel_encargo(id)` (below).
  - Reject of a request whose action is `encargo` also sets the encargo `rejected` (expect `pending_approval`).
  - `encargo_step() -> bool` (exposed as `app.state.encargo_step`): takes `db.encargo_next()`; if `queue_paused()` → status `paused`, return False; on first start of a queued one (empty `units`, `done == 0`) builds the units from `db.doc_texts` (snapshot) via the operation and stores them; runs the unit at index `done` with `local_complete` (3 tries, 30 s apart; wait attribute overridable for tests) → `op.after`, appends follow-up units, increments `done`, adds the device to `devices`, records seconds per unit as an EMA in setting `encargo_s_per_unit`; when `done == len(units)` → `result = op.render(...)`, status `done` then immediately `kept` if not `to_claude`, logs `encargo_done` {id, docs, units, seconds}. A unit that exhausts tries → `failed`, `error` = «Un trozo falló 3 veces en <equipo>.», partial `result` rendered, log `encargo_failed`. Status re-read before saving each unit: if it became `cancelled`, discard the answer. Returns True if it did work.
  - Worker: `app.state.encargos_due()` (called from the maintenance loop) starts one daemon thread `encargos` if none alive and `encargo_next()` exists; the thread loops `encargo_step()` until it returns False with nothing runnable, sleeping 5 s while paused.
  - `cancel_encargo(eid) -> str` — from any unfinished status → `cancelled`; else HTTP 409 «El encargo ya terminó.».
  - Endpoints (all `require_admin`): `GET /api/encargos` (list incl. `label`, progress `done/total`, no units, `result` only when status in done/kept/released/failed), `POST /api/encargos/{id}/release` (expect `done` and `to_claude` → `released`), `POST /api/encargos/{id}/keep` (expect `done` → `kept`), `POST /api/encargos/{id}/cancel`. Wrong state → 409 with Spanish detail.
  - `GET /api/claude-requests` rows with action `encargo` carry `encargo: {op, label, docs: [names], to_claude, estimate}`.
  - `NOTIFY_CATS["encargos"] = "Un encargo de Claude terminó (o falló)"`; `notify_due` turns `encargo_done` / `encargo_failed` into «Encargo listo» / «Un encargo falló» opening `/#encargos`.
  - Restart resume (Review Focus 2): a `running` encargo picked again redoes unit `done` (the in-flight one), never advances twice.
