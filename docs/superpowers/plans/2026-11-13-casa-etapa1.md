# Casa, etapa 1 (casas y dispositivos) — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una pestaña «Casa» en el panel que lee los dispositivos de Home Assistant de Bogotá, agrupados por área, y permite controlar luces, enchufes, escenas, cerraduras y garaje.

**Architecture:** Un módulo nuevo `core/casa.py` con:
- un cliente REST de Home Assistant (con `httpx`, que ya es dependencia);
- funciones puras que arman la vista y traducen acciones a servicios.

Los endpoints van en `core/app.py`. Hay dos tablas nuevas en `core/db.py`. La pestaña se agrega a `core/ui/index.html`. La casa se configura con variables de entorno en ZimaOS.

**Tech Stack:** Python 3, FastAPI, SQLite, httpx, pytest; panel en HTML/JS sin framework.

**Spec:** `docs/superpowers/specs/2026-11-13-casa-design.md` (§5.2, §5.4, §5.7, §5.8, §6 etapa 1)

## Global Constraints

- **No hay dependencias nuevas.** El diseño (§5.2) pedía WebSocket. En la etapa 1 se usa REST con caché de 3 s, porque `httpx` no hace WebSocket y agregar `websockets` es una dependencia nueva. El WebSocket queda para cuando haga falta (etapa 4, eventos). **Sergio lo valida al revisar este plan.**
- **Cambio de esquema aprobado con el diseño:** solo `casas` y `casa_dispositivos` en esta etapa. `casa_energia` y `casa_eventos` llegan en las etapas 2 y 4.
- **El token nunca va en la base, ni en logs, ni en respuestas.** La base guarda solo el nombre de la variable (`ASHUR_HA_TOKEN`).
- **Variables de entorno:**
  - `ASHUR_HA_URL` (sin ella, la pestaña dice «Home Assistant no está configurado»);
  - `ASHUR_HA_TOKEN`;
  - `ASHUR_CASA_NOMBRE` (por defecto `Bogotá`).
- **Aprobaciones (§5.4):**
  - Luces, enchufes y escenas van directo.
  - Cerraduras y garaje piden `confirm: true` (si falta, responde 409 con el texto para el diálogo).
  - Ocultar o mostrar un dispositivo es «quitar o agregar un dispositivo de la casa», así que también pide `confirm: true`. El panel lo confirma en pantalla con la clave admin; mientras no exista la llave maestra, cualquier equipo con la clave admin aprueba (regla vigente).
  - Ordenar y marcar favorito van directo.
- **Solo Sergio:** todos los endpoints usan `require_admin`. Los invitados no ven la pestaña.
- **Controlables en la etapa 1:** `light`, `switch` (on/off), `scene` (activar), `lock` (bloquear/desbloquear), `cover` con `device_class` `garage` (abrir/cerrar). Todo lo demás es solo lectura, incluida `alarm_control_panel`, porque desarmar pide un código que no se maneja en esta etapa.
- **La potencia** se muestra solo en las entidades `sensor` con `unit_of_measurement` `W` o `kW`, como filas de lectura. Unir un enchufe con su sensor necesita el registro de dispositivos de Home Assistant (WebSocket) y queda para la etapa 2.
- **Logs cortos:**
  - `casa_control` con `{casa, entity, accion, ok}`;
  - `casa_ha_falla` con `{casa, motivo}`, como máximo uno cada 10 minutos por casa;
  - `casa_dispositivo` con `{casa, entity, cambio}`.
- **Textos al usuario en español:**
  - «Home Assistant no responde» + la hora de la última vista;
  - «El token de Home Assistant no es válido»;
  - «Home Assistant no está configurado».
- **Versión 0.57.0:** se actualizan `core/app.py`, `CHANGELOG.md` y `deploy/zimaos-compose.yaml` (las variables, comentadas y sin valores).
- **Panel:** sin parpadeo. En cada refresco solo cambian los textos de estado y potencia; la lista se reconstruye solo si cambia el conjunto de entidades.

## Review Focus

1. **Home Assistant caído o lento (timeout de 5 s):** GET responde 200 con `ha: "sin_respuesta"`, la última vista y los últimos datos en caché. Nunca 500. El control responde 502 con el texto.
2. **Token inválido (Home Assistant responde 401):** `ha: "token_invalido"` y el log, una vez.
3. **Entidad que ya no existe en Home Assistant** pero tiene preferencias guardadas: no aparece en la vista. Controlarla responde 404.
4. **Cerradura o garaje sin `confirm`:** 409 y no se llama a Home Assistant.
5. **Dominio no controlable** (`sensor`, `alarm_control_panel`, `climate`): 400 y no se llama a Home Assistant.

**Interfaces:**
- Produces:
  - `DB.casa_ensure(nombre: str, ha_url: str, ha_token_env: str) -> int`: crea la fila si no hay ninguna con ese `ha_url`; si existe, actualiza el nombre. Devuelve el id.
  - `DB.casas() -> list[dict]`: devuelve `id, nombre, ha_url, ha_token_env, tz, nivel_energia_def`, ordenadas por id.
  - `DB.casa_get(cid: int) -> Optional[dict]`.
  - `DB.casa_disp_set(casa_id: int, entity_id: str, **cambios) -> None`, con `cambios` en {`orden`, `favorito`, `oculto`}: upsert.
  - `DB.casa_disps(casa_id: int) -> dict[str, dict]`: devuelve, por entity_id, `{orden, favorito, oculto, nivel_energia}`.

Esquema:

```sql
CREATE TABLE IF NOT EXISTS casas (            -- casa (0.57.0): one per Home Assistant; the token lives in ZimaOS, never here
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre            TEXT NOT NULL,
    ha_url            TEXT NOT NULL UNIQUE,
    ha_token_env      TEXT NOT NULL,
    tz                TEXT NOT NULL DEFAULT 'America/Bogota',
    nivel_energia_def INTEGER NOT NULL DEFAULT 1 CHECK (nivel_energia_def IN (1, 2, 3))
);
CREATE TABLE IF NOT EXISTS casa_dispositivos ( -- only what Ashur adds on top of Home Assistant
    casa_id       INTEGER NOT NULL REFERENCES casas(id),
    entity_id     TEXT NOT NULL,
    orden         INTEGER NOT NULL DEFAULT 0,
    favorito      INTEGER NOT NULL DEFAULT 0,
    oculto        INTEGER NOT NULL DEFAULT 0,
    nivel_energia INTEGER CHECK (nivel_energia IN (1, 2, 3)),   -- null: the house's level (stage 2)
    PRIMARY KEY (casa_id, entity_id)
);
```

### Task 2: `core/casa.py` — cliente de Home Assistant y vista

**Files:**
- Create: `core/casa.py`
- Test: `tests/test_casa.py`

**Interfaces:**
- Produces:
  - `class HAError(Exception)` con `motivo: str` en {`sin_respuesta`, `token_invalido`, `error`}.
  - `class HAClient(base_url: str, token: str, http: Optional[httpx.Client] = None, timeout: float = 5.0)`:
    - `.states() -> list[dict]`: `GET /api/states`.
    - `.areas() -> dict[str, str]`: entity_id → nombre del área, vía `POST /api/template` con `AREAS_TEMPLATE`.
    - `.call(domain: str, service: str, entity_id: str) -> None`: `POST /api/services/{domain}/{service}`.
    - Errores: un 401 lanza `HAError("token_invalido")`; un timeout o error de conexión lanza `HAError("sin_respuesta")`; otro código ≥400 lanza `HAError("error")`.
  - `ACCIONES: dict[str, dict[str, str]]`: dominio → {acción del panel → servicio de HA}:
    - `light`/`switch`: `{"on": "turn_on", "off": "turn_off"}`;
    - `scene`: `{"activar": "turn_on"}`;
    - `lock`: `{"bloquear": "lock", "desbloquear": "unlock"}`;
    - `cover`: `{"abrir": "open_cover", "cerrar": "close_cover"}`.
  - `CONFIRMAR = {"lock", "cover"}`.
  - `def controlable(state: dict) -> bool`: el dominio está en `ACCIONES`; para `cover`, además, `attributes.device_class == "garage"`.
  - `def servicio(state: dict, accion: str) -> tuple[str, str]`: devuelve `(domain, service)` o lanza `ValueError`.
  - `def vista(states: list[dict], areas: dict[str, str], prefs: dict[str, dict]) -> dict`:
    - Devuelve `{"favoritos": [disp], "areas": [{"nombre": str, "dispositivos": [disp]}], "ocultos": [disp]}`.
    - Cada `disp` es `{entity_id, nombre (friendly_name o entity_id), dominio, estado, area, controlable, confirmar, potencia_w (float|None), favorito, orden}`.
    - Solo entran los dominios controlables y los `sensor` de W/kW (los kW se convierten a W).
    - Los ocultos salen de `areas` y `favoritos`.
    - Sin área va a «Sin área», que siempre es la última.
    - Dentro de cada lista se ordena por `(orden, nombre)`.

`AREAS_TEMPLATE` (cadena exacta; Home Assistant la devuelve como texto JSON):

```jinja
[{% for a in areas() %}{% set n = area_name(a) %}{% for e in area_entities(a) %}["{{ e }}", {{ n | tojson }}]{% if not loop.last %},{% endif %}{% endfor %}{% if not loop.last and area_entities(a) %},{% endif %}{% endfor %}]
```

Esa plantilla puede dejar una coma colgando cuando un área sin entidades queda al final. `areas()` lo resuelve parseando con `json.loads` después de limpiar `,]` y `,,` con una regex.

- Produces:
  - **`create_app(..., ha_url: Optional[str] = None, casa_nombre: str = "Bogotá", ha_token_env: str = "ASHUR_HA_TOKEN", ha_client_fn: Optional[Callable[[str, str], HAClient]] = None, env: Mapping[str, str] = os.environ)`**: si hay `ha_url`, `casa_ensure(casa_nombre, ha_url, ha_token_env)` al arrancar. El token se lee de `env[row["ha_token_env"]]` en cada uso.
  - **`GET /api/casa?casa=<id>`**:
    - Respuesta: `{"casas": [{"id", "nombre"}], "casa": id|None, "ha": "ok"|"sin_respuesta"|"token_invalido"|"error"|"sin_configurar", "visto": ts|None, **vista}`.
    - La caché es por casa: estados 3 s y áreas 300 s, según `clock`.
    - Si Home Assistant falla, se devuelven los últimos datos en caché con `ha` y `visto`.
    - Sin casas configuradas: `ha: "sin_configurar"`, `casa: None` y listas vacías.
  - **`POST /api/casa/{cid}/control`** con body `{"entity_id": str (máx. 255), "accion": str (máx. 24), "confirm": bool = False}`. Respuestas:
    - 404 si la casa o la entidad no existen en los estados actuales;
    - 400 «Ese dispositivo no se controla desde Ashur» si no es controlable o la acción no aplica;
    - 409 `{"detail": "confirmar", "texto": "¿Desbloquear Puerta entrada?"}` si el dominio está en `CONFIRMAR` y no viene `confirm`;
    - 502 con el texto del motivo si Home Assistant falla;
    - en el éxito, `{"ok": True}`, se invalida la caché de estados y se registra `casa_control`.
  - **`PUT /api/casa/{cid}/dispositivo`** con body `{"entity_id": str, "favorito": Optional[bool], "orden": Optional[int], "oculto": Optional[bool], "confirm": bool = False}`. Si cambia `oculto` sin `confirm`, responde 409 `{"detail": "confirmar", "texto": "¿Quitar <nombre> de la casa?"}` (o «¿Volver a mostrar…?»). Registra `casa_dispositivo`.
  - **`serve.py`**: lee `ASHUR_HA_URL` (vacío → None) y `ASHUR_CASA_NOMBRE`. Al arrancar imprime una línea: `casa: <nombre> → <url>` o `casa: sin Home Assistant`, nunca el token.

Comportamiento (§5.8, versión de la etapa 1: sin cámaras ni energía todavía):

- **Arriba:** «Casa» y una pastilla con el nombre de cada casa. Con una sola casa no se ve el «+».
- **Estado de Home Assistant:** si `ha != "ok"`, una línea con el texto en español (Global Constraints) y «visto hace N min», en `--amber`. Nunca en rojo, porque una conexión perdida no es una emergencia, igual que en el subtítulo actual.
- **Favoritos primero.** Después, un bloque por área con sus filas:
  - nombre;
  - estado o potencia en `--mono` con `--tint` («86 W», «encendida», «bloqueada»);
  - un interruptor para `light`/`switch`, un botón «Activar» para `scene`, y botones de acción para `lock`/`cover`.
- **Confirmaciones:** al recibir 409 `confirmar`, se muestra el `texto` en una confirmación del propio panel (no `window.confirm`) y se reenvía con `confirm: true`.
- **Modo «Organizar»** (un botón al pie): en cada fila aparecen la estrella de favorito, subir y bajar (cambian `orden`) y «Quitar» (oculto, con confirmación). Abajo, «Ocultos (N)» con «Volver a mostrar».
- **Refresco:** cada 5 s mientras la pestaña está visible, y nunca con la pestaña oculta (`document.hidden`). Solo cambia el `textContent` de estado y potencia, buscando las filas por `data-entity`. La lista se reconstruye solo si cambia la lista de entity_id.
- **Interruptores:** responden al toque de forma optimista y vuelven atrás si el POST falla, mostrando el error en la fila.
- **Visibilidad:** la pestaña se oculta para `role === "self"` (invitado), igual que `tab-status`.
